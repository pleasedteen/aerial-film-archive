# 航拍底片扫描件采集项目

把地方测绘档案馆旧航拍底片的模拟站点内容采集到本地，供编目员查阅。
**纯 Python 标准库实现，无第三方依赖**，包含一个自带的、确定性可回放的 HTTP 模拟站。

## 目录结构

```
aerial_crawler/
├── aerial/                # 采集端
│   ├── config.py          # 运行配置（间隔、并发、退避、补登窗口等）
│   ├── limiter.py         # 全站共享的最小发起间隔限流器 + 统一暂停
│   ├── http.py            # 退避重试 / 503 统一暂停 / Range 分段的 HTTP 客户端
│   ├── parsing.py         # 分页目录与卷宗详情 HTML 解析
│   ├── state.py           # 工作目录状态（水位、版本基线、翻页断点、失败队列、锁）
│   ├── manifest.py        # JSON Lines 事件清单 + 每卷当前条目原子视图
│   ├── downloader.py      # 分段下载、断点区段复用、sha256 校验装配
│   └── scanner.py         # 全量 / 增量采集调度、worker 池、补齐轮次
├── mocksite/              # 可回放的 HTTP 模拟站
│   ├── scenario.py        # 固定场景 / 200 页大目录场景、20 倍速虚拟时钟
│   └── server.py          # 分页目录 / 详情 / Range 影像 / 故障注入 / 限流 / 请求统计
├── tests/test_rules.py    # 规则级单元测试（unittest）
├── verify.py              # 一条命令的端到端验证（80 秒内出可读报告）
├── verify_large.py        # 大目录增量验证（200 页历史 / 3 处变化 / 强杀续采）
└── README.md
```

## 一、启动模拟站

```bash
python3 -m mocksite --host 127.0.0.1 --port 8080
# 可选 --rate 20：虚拟站点时钟相对真实时间的倍速（默认 20）
```

- 所有响应带头 `X-Site-Time`（虚拟站点秒，基准 `1700000000`），一切更新时间 /
  补登判定均以**站点时间**为准；
- 路由：
  - `GET /catalog?page=N` 分页 HTML 目录（按更新时间倒序，含重复链接）；
  - `GET /volumes/<卷宗号>` 卷宗详情：卷宗编号、按秒版本更新时间、sha256 校验值、大小；
  - `GET /images/<卷宗号>` 影像，支持 `Range` 分段读取，**换版后下载地址沿用**；
  - `GET /healthz` 健康检查（不限流）；
  - `GET /stats`、`GET /stats/reset` 按类别（目录页 / 详情 / 影像）统计成功请求数。
- 内置场景：
  | 卷宗 | 场景 |
  |---|---|
  | V0003 | 目录中重复出现链接 |
  | V0002 | 影像头两次请求 500，验证退避重试 |
  | V0005 | 影像首次请求 503 + `Retry-After`，验证统一暂停 |
  | V0006 | 换版：v2 更新时间严格递增，下载地址沿用 |
  | V0007 | 补登：更新时间后 120 站点秒才上目录（10 分钟窗口内），影像再晚 60 秒开放 |
  | V0008 | 大卷宗，用于中断恢复 |
- 大目录场景（`--history-pages 200`）：历史卷宗占满 200 页，另有 3 处变化
  （换版、与水位同秒的换版、窗口内漏登），配合 `--start-site-time` 可从任意
  站点时刻起跑；`--catalog-delay` 给每页目录加真实延迟，便于验证强杀续采。
- 服务端另有 1 秒滚动窗口限流（默认 14 请求/秒），超出返回 503 + `Retry-After`。

## 二、全量采集

```bash
python3 -m aerial \
  --base-url http://127.0.0.1:8080 \
  --workdir ./data \
  --workers 4 --min-interval 0.05 \
  full
```

全量会翻完整个目录，对每卷拉详情、分段下载影像、校验后入库。
常用参数：

| 参数 | 含义 | 默认 |
|---|---|---|
| `--workers` | 并发 worker 数（共用一个限流器） | 4 |
| `--min-interval` | 全站统一的最小请求发起间隔（秒） | 0.05 |
| `--chunk-size` | 分段下载区段大小（字节） | 65536 |
| `--retry-rounds` | 主扫描后的补齐轮数 | 4 |
| `--retry-round-interval` | 补齐轮之间等待秒数 | 1.0 |
| `--max-retries` | 单请求最大重试次数 | 6 |

## 三、增量采集

```bash
python3 -m aerial --base-url http://127.0.0.1:8080 --workdir ./data incremental
```

使用**同一工作目录**。增量只查两类范围（以站点时间为准）：

1. **上次扫描以来的更新**：已知卷宗中目录 `updated_at` **严格大于本地已校验
   版本 `updated_at`** 的条目（换版）。相等即未变，不拉详情；
2. **仍可能补登的范围**：`上次扫描水位 - 10 分钟`（`--backfill-seconds`，默认
   600）地平线之内的未知卷宗；更旧的未知条目不查。

**有上限的翻页**：目录按更新时间倒序，一页里最新的条目都低于地平线时就停止
翻页。大目录里每天只变几卷，增量不会翻完整个目录；未变卷宗不查详情。

**停采也不漏**：地平线只看“上次扫描水位”，不看“现在”。即使停采远超十分钟，
也只需回看到上次扫描时仍可能迟到补登的范围——漏登条目（窗口内才上目录）与
与水位**同秒**发生的换版（`updated_at` 恰等于水位）都仍会被找回。水位只在整轮
扫描成功结束后推进，中途失败不会把它当成已完成。

**水位取“本次扫描启动那一刻”**的站点时间：扫描期间才生效、但本次未采到的
更新，下一次增量仍会被复查，不会被水位永久跳过。翻页期间插入的条目由补齐轮次
从首页复查（同样到地平线即停）发现，最迟下一轮入库。

**强杀续采**：每翻完一页就把“下一页地址 + 本轮已接受候选”原子落盘到
`state/scan.json` 与 `state/scan.candidates.jsonl`。用原工作目录重跑时从断点页
继续，不重读已确认的目录页；候选重新入队时，已完成版本按校验值/清单原地复用。
断点只在模式与扫描前水位都对得上时沿用，否则按新一轮处理。

## 四、工作目录与产物

```
data/
├── state/
│   ├── state.json      # 模式、扫描水位、已知卷宗、每卷已入库版本基线（原子写）
│   ├── scan.json       # 目录翻页断点：下一页地址、已确认页数、补齐轮进度
│   ├── scan.candidates.jsonl  # 本轮已接受的候选（逐页 fsync，续采用）
│   ├── failed.json     # 待补齐卷宗及尝试次数（原子写，清空时可能不存在）
│   └── lock            # 单实例文件锁
├── manifest/
│   ├── events.jsonl    # 只追加的事件流，采集期间编目员可随时逐行读取
│   └── current.json    # 每卷唯一一个当前条目（原子替换）
├── images/<卷宗号>/
│   ├── v<n>_<校验前缀>.img   # 校验通过的完整影像（不可变，旧版保留）
│   └── chunks/...            # 下载中的持久化区段（装配后清理）
└── logs/run.log
```

关键保证：

- **每卷只有一个当前条目**，始终指向校验通过的完整影像；
- **替换件校验通过前旧件继续可查**，`current.json` 用临时文件 + 原子替换切换；
- **较晚完成的旧版下载不会让清单回退**：提交时按 `updated_at` 单调保护，
  旧版完成只记 `superseded` 事件；
- **同一卷同一版本的重复链接只拉一份完整影像**（目录去重 + 已校验影像复用）；
- **进程被 `kill -9` 后用原工作目录续采**：已 fsync 的区段按长度校验后直接复用，
  只补缺档；状态/清单文件均为原子写，不会出现半截 JSON；
- 下载暂时失败的卷宗进入持久化失败队列，主扫描与其他卷宗继续，
  随后由补齐轮次重试；补齐轮次从目录首页复查到地平线，捕获迟到的补登、
  与水位同秒的换版、以及翻页期间插入的条目。

退出码：`0` 全部完成；`2` 仍有卷宗待补齐（状态已落盘，再跑一次即可续）；
`73` 工作目录被其他进程占用。

## 五、一条命令完成端到端验证（80 秒内）

```bash
python3 verify.py
```

自动找空闲端口、起模拟站、建临时目录，依次覆盖**补登、限流、换版、中断恢复**，
最后打印逐条 PASS/FAIL 报告与总用时（实测约 47 秒，稳定可回放）。
需要保留现场时：

```bash
python3 verify.py --workdir ./verify_data --keep
```

验证脚本内部会：全量下载中 `SIGKILL` 强杀 → 同目录续采并断言“复用 N 段” →
等到补登条目与换版生效后跑增量 → 对所有当前影像重新计算 sha256 比对。

## 六、大目录增量验证

```bash
python3 verify_large.py            # 约 35 秒
python3 verify_large.py --keep     # 保留现场
```

在模拟站上造一个 **200 页历史目录 + 3 处变化** 的站点，分两个场景断言：

- **有上限的增量**：上次扫描水位 600、现在站点时间 3600（停采 50 分钟）时做
  增量，断言（1）目录页请求 ≤ 4 次（含补齐轮次复查）；（2）只有 3 处变化拉
  详情，200 页历史卷宗一条不查；（3）与水位同秒的换版、水位前 120 秒更新的
  漏登卷宗都被找回；日志出现“增量提前结束翻页”。
- **强杀续采**：让增量必须翻完 40 页（每页加延迟），翻到第 5 页后 `SIGKILL`；
  用同一工作目录重跑，断言续采主扫描从断点页（第 6 页）开始、不重读已确认
  的 1–5 页；翻页期间才上目录的条目由补齐轮次发现并入库。
